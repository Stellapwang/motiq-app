Notes for the app developer

Four things a web build cannot do. Nothing here is an examiner action.

1. Pen and touch are not simultaneous. While an Apple Pencil is in contact, iPadOS discards concurrent finger touches as palm contact, and no web API turns that off. PEN_TONE and PEN_FAST therefore do not run as true dual tasks here. Flagged in the data.

2. Pencil hover height is unavailable. The platform reports where the pen hovers, never how high. Hover at all needs an M2 iPad: measured 2026-09-11, none on an 11-inch M1 iPad Pro, about 59 Hz on the M2.

4. This is a prototype instrument. Millimeters come from a card calibration and timing from the browser clock. Both are approximate and should be reported as such.

→ The native iPadOS build exists for 1 and 2. It must:

  • deliver pencil and touch as separate simultaneous streams (UIKit does; Safari does not);
  • record hover onset and hover dwell before first contact, separately from time-to-first-contact;
  • record the height profile through the descent — steady, stalled, or repeatedly approaching and withdrawing. A web build cannot capture this at all;
  • record pen lifts during drawing as first-class events, with count and duration, rather than inferring them from stroke boundaries.

Full rationale, and the caveat about verifying the UIKit API rather than trusting a remembered symbol name, are in the PENCIL HOVER comment block in this file's source.

Room check — per session, per room

Five seconds of silence with nobody speaking. It measures the background noise floor, which is what makes a voice recording scoreable or not: speech has to sit far enough above the room. The published minimum is 30 dB of signal-to-noise, with over 42 dB recommended (Deliyski et al. 2005, J Voice 19:15). Without a noise floor there is no way to tell a quiet participant from a noisy room — and that distinction matters, because recording geometry moves the level far more than the voice disorder does.

Pen check — per participant, per hand

One spiral on each hand, measured for sample rate, pressure and pointer type. The reading goes into every trial record as pen_check, and is what implement_verified is judged against: a stylus the device never reported as a stylus is a trial whose implement is the examiner's claim rather than a measurement. This is not the participant's practice — that is administered inside the session, on each task, with that task's own rules. Draw it yourself if you prefer; what is being checked is the device.

Touch check — per device

Ten seconds of tones with a target to tap, to confirm taps register and to see which pointer type they arrive as. Nothing here is scored and nothing is recorded; the tapping tasks are demonstrated rather than practised, which is what the task description asks for. The tones here are something to tap to, not a hearing check — they play at whatever volume is set. What the participant can hear is the sound check on the next page, and the audibility check inside the session.

Play both tones at the level the session will use. The participant must hear the difference easily — this is not a discrimination test. Fix the volume here and do not change it during the session.

How a trial ends. There are only three ways, and END always works.
WayWhenWhich tasks
You press END Any time. Nothing overrides it. Every task.
Its length runs out The trial stops itself when the set length is reached. Tasks with a fixed length in the Length column: TAP_FAST, TAP_BMIN, TAP_BANT, TAP_TONE, VOC_VODD.
Idle auto-stop The trial stops itself once the screen has been untouched for the number of seconds set here. Tasks with no fixed length, which is every drawing task.
A drawing task set to "Draws for 60 s" does not stop at 60 seconds. The 60 seconds is the window that decides which drawing counts as data. When it runs out the participant sees END and is told to stop, and the trial keeps recording until you press END or the screen goes idle. Idle auto-stop is switched off for the whole of those 60 seconds, so a pause between finishing one spiral and starting the next can never end the trial. This applies to PEN_SPR60, PEN_VODD and every other spiral task with a window set.

The "Remind me after" box, above. Once a trial has been running for that many seconds, one line appears on the examiner's side of the screen saying how long it has been going. That is all it does. It is there in case a trial has been left open by accident, and it never stops a trial: a slow participant can legitimately take three minutes over a spiral, so nothing is ever cut off because of it. Set it to whatever length would make you look up.

Auditory stream

Per-task defaults. Edit a row to change what that task uses for the rest of the session.

SettingWhat it isRange
Standard (Hz) The pitch of the common, low beep — the one that is ignored on an oddball and answered on every other stream. 500–1500 Hz.
1000 is the default.
Target (Hz) The pitch of the rare, high beep. What matters is the SEPARATION from the standard, not the absolute pitch: the two must be told apart instantly by someone who is also drawing, so this is not a discrimination test. An octave (double the standard) is unmistakable. Below about 1.3× they start to be confusable under load. Keep both under 4 kHz, where age-related hearing loss begins to bite. 1.5–2× the standard.
2000 against 1000 is the default.
Tone level Not the volume. It is the digital amplitude of the synthesised tone BEFORE the iPad's own volume control: 1.0 is the loudest undistorted signal, 0.5 about −6 dBFS. Loudness is set with the iPad's volume buttons and confirmed in the sound check; this only decides how much headroom there is above the digital noise floor. Leave it alone. 0.05–1.0.
Leave at 0.5.
Sequence Where the random stream comes from. Matched gives every participant the same stream for a given task and repeat, so a difference between two people is a difference between the people. New random each trial gives a fresh stream every time, which is right for piloting and wrong for comparing. Fixed seed gives one single stream everywhere, including across different tasks. Matched, for a study.

Saved trials on this device
Trials are written when you press SAVE. This is browser storage, not a database — clearing Safari's website data erases it. Export at the end of every session.

parameters_json carries the complete parameter set verbatim, so a setting added later is still recorded in full for trials run today.

The JSON export is one object with three sections — trials, screening and audio_index. The CSV buttons write the trial rows and the screening rows as two separate files, because they have nothing in common to share columns with.
Screening screens on this device
One row per administration rather than per trial: these are participant-level covariates and are stored separately from the trial file. No screen in the current build writes here — records from retired screens are still listed and exported, so nothing already collected is stranded.
Voice recordings on this device
Clips are held in IndexedDB rather than the approximately 5 MB string store used for trials, and each file is named after its trial. A bulk download starts one download per clip. Safari may request permission for multiple downloads and may refuse them if the page is not in the foreground; download individually if this occurs.
