Known limitations

1. Pen and touch input are not simultaneous. While an Apple Pencil is in contact with the screen, iPadOS classifies concurrent finger touches as palm contact and discards them. This cannot be changed from a web page. PEN_TONE and PEN_FAST are affected: tap responses are not recorded while the pen is down, so these do not run as true dual tasks in this prototype. Trials still record, and the limitation is flagged in the data.

2. Pencil hover height cannot be measured from a web page. An Apple Pencil is detected while its nib is roughly 1–12 mm above the display. A web page can be told where the pen is hovering, but nothing in the web platform reports how high it is: there is no standard property for the distance above the glass, and the Pointer Events proposal to add one is unresolved. A web build therefore knows the pen is somewhere in that 12 mm band, not where in it. Hover is also gated on the iPad itself: it arrived with the M2 generation. Measured 2026-09-11 — on an 11-inch iPad Pro 3rd generation (M1) there is no hover at all, the pen being undetectable until it touches; on a 4th generation (M2) hover works, at about 59 Hz. So hesitation before a participant commits to the first stroke can be measured, but only on an M2 iPad — on the M1 it is not merely unmeasured, it is unmeasurable. The height of the pen above the glass is unavailable on both.

→ Required in the native iPadOS build

Items 1 and 2 above are the two reasons the native build exists. Neither is a defect in this prototype and neither can be fixed in a web page. The native instrument must:

  • deliver pencil and touch as separate simultaneous streams, so a spiral-plus-tap condition runs as a genuine dual task (UIKit does this; Safari does not);
  • record hover onset, and hover dwell before first contact separately from time-to-first-contact, so hesitation with the pen raised is distinguishable from hesitation with the pen nowhere near the glass;
  • record the height profile through the descent — whether the pen comes down steadily, stalls partway, or repeatedly approaches and withdraws. This is the measure a web build cannot capture at all;
  • record pen lifts during drawing as first-class events, with count and duration, rather than inferring them from stroke boundaries.

Full rationale, and the caveat about verifying the exact UIKit API rather than trusting a remembered symbol name, are in the PENCIL HOVER comment block in this file's source.

3. Voice recording requires an https address. Microphone access is available only over https, or from localhost and 127.0.0.1. When the app is opened from a plain http:// address on a local network, the spoken tasks run but record no audio. This depends on the address the page was opened from, not on the device.

4. This is a prototype instrument. Millimeters are derived from a card calibration and timing from the browser clock. Both are approximate and should be reported as such.

Pen check — per participant

Ask the participant to draw the spiral below, once with each hand. This checks that the stylus registers, that samples arrive at a usable rate, and that pressure varies. A spiral is used rather than a straight line: the same four measures are obtained over a longer stroke, so the sample-rate estimate is less dependent on stroke length, and it familiarizes the participant with the spiral instruction. This is a device check, not a trial; no trial record is written.

Dot tap screen — screening, per participant

Ten seconds. A dot appears somewhere in the box; the participant taps it, and the next one appears somewhere else. Tell them to tap each dot as soon as they see it. A dot that is not tapped within 1.5 s counts as a miss and disappears on its own.

Sound check — per participant

Play both tones at the level the session will use. The participant must hear the difference easily — this is not a discrimination test. Fix the volume here and do not change it during the session.

Room check

Five seconds of silence, once per session, with nobody speaking. It measures the background noise floor, which is what makes a voice recording scoreable or not: speech has to sit far enough above the room. The published minimum is 30 dB of signal-to-noise, with over 42 dB recommended (Deliyski et al. 2005, J Voice 19:15). Without a noise floor there is no way to tell a quiet participant from a noisy room — and that distinction matters, because recording geometry moves the level far more than the voice disorder does.

Saved trials on this device
Trials are written when you press SAVE. This is browser storage, not a database — clearing Safari's website data erases it. Export at the end of every session.

parameters_json carries the complete parameter set verbatim, so a setting added later is still recorded in full for trials run today.

The JSON export is one object with three sections — trials, screening and audio_index. The CSV buttons write the trial rows and the screening rows as two separate files, because they have nothing in common to share columns with.
Screening screens on this device
One row per administration rather than per trial. The dot tap screen is a participant-level covariate and is stored separately from the trial file. Records from screens that have since been retired are still listed and exported here.
Voice recordings on this device
Clips are held in IndexedDB rather than the approximately 5 MB string store used for trials, and each file is named after its trial. A bulk download starts one download per clip. Safari may request permission for multiple downloads and may refuse them if the page is not in the foreground; download individually if this occurs.
